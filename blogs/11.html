并查集学习笔记

August 11, 2026

这个页面介绍并查集。

朴素并查集

考虑这个问题：

初始时有 \(n\) 个节点，它们之间没有任何边。有 \(m\) 个操作，每次操作要么加入一条无向边，要么给定两个节点并询问它们是否在一个连通块内。

一般的想法是不断地跑 DFS 来判断是否在一个连通块内，但这样的查询操作是 \(O(n+m)\) 的，非常糟糕。

于是我们可以给每个节点赋一个指针，那么一个连通块中只有一个节点 \(u\) 使得它指向自己，我们把它记作 \(\text{find}_v\)，\(v\) 可以是该连通块中任意一个节点。

画成图就是一个类似树的东西，\(\text{find}_v\) 就是 \(v\) 所在的树的根，可以用一个递归函数来查找。

一开始，所有节点的指向它自己，即 \(\text{tag}_i=i\)。

最后可以发现加边操作就是合并两个连通块，所以在 \(u\) 和 \(v\) 之间加一条边就相当于令 \(\text{tag}_{\text{find}_v}=\text{find}_u\)，反过来也可以。

大功告成！

int tag[N+5];

int find(int x) {
    if(x==tag[x]) return x;
    return find(tag[x]);
}

void unite(int u, int v) {
    tag[find(v)]=find(u);
}

这个数据结构就是并查集。

路径压缩

但是这样做的话，树的形态可以是一条链，那么单次操作的复杂度就变成了 \(O(n)\)。

所以我们可以在 find 的过程中把这棵树拍扁，让 \text{tag}_v 直接变成 \(\text{find}_v\)，这样节点的深度就能大大降低了。我们把这种优化方式称为路径压缩。

它的代码也很简单，只要把 find 改成这样：

int find(int x) {
    if(x==tag[x]) return x;
    return tag[x]=find(tag[x]);
}

在这里测试：https://www.luogu.com.cn/problem/P3367

但路径压缩的复杂度很神秘，应该是 \(O(\log n)\) 级的。

例题一：Color the Axis

原题：https://www.luogu.com.cn/problem/P1840

把每个连续的白色块当成一个连通块，那么就可以用并查集来做，\(\text{find}_v\) 指 \(v\) 所在连通块的左端点。每次对一个区间染色就暴力地从右端点跳到左端点。

为什么它的复杂度是对的呢？因为我们每跳一次，就会把一个黑点变成白点，一共有 \(n\) 个点，就要跳 \(n+O(1)\) 次。

例题二：上帝造题的七分钟 2 / 花神游历各国

原题：https://www.luogu.com.cn/problem/P4145

首先当 \(1\le x\le 10^{12}\) 时，我们在 \(6\) 次开平方操作之内就能把它变成 \(1\)。

所以与上一题类似，把已经变成 \(1\) 了的连续的数当成一个连通块，再用树状数组维护区间和就行了。

总结一下，路径压缩的优势就是能保存根节点的信息，我们可以利用这点做一些区间上的问题。

启发式合并

这是另一种优化方式。

在每次合并时，显然我们把大小较小的连通块连到较大的连通块上是更优的。假设以 \(v\) 为根的子树大小是 \(\text{siz}_v\)，那么优化后总有 \(\text{siz}_{\text{tag}_v}\ge 2\text{siz}_v\)。也就是 find 中每次递归时树的大小都会翻倍，树高就会是 \(O(\log n)\) 级的。

如果有特别的条件也可以实现撤销合并的操作。

并且你可以同时使用路径压缩与启发式合并，这可以使单次查询的时间复杂度变为 \(O(\alpha(n))\)，你可能不知道这是什么，但只要知道它很小就行了，\(\alpha(10^{18})\le 10\)。

同时如果我们把根节点的信息在合并时也进行转移的话，就可以维护每个连通块的最值等。

习题：https://www.luogu.com.cn/problem/P3295
